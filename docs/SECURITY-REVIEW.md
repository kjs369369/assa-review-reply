## 배포 기준 업데이트 — 정적 브라우저 앱

2026-09-26: 공개 배포는 GitHub Pages의 정적 파일만 사용한다. 리뷰 처리를 브라우저로 이동해 API 호출·계정·세션·저장소·서버 데이터 처리를 제거했다. 이전 단일 Node 서버와 인증 모듈은 공개 파일에 포함하지 않는다. 아래 초기 서버 보안 기록은 현재 배포 구조의 설명이 아니다.

배포 전 확인: 입력 검증과 textContent 출력 유지, 위험한 URL 차단, 비밀 파일 제외, 외부 스크립트 없음, 런타임 의존성 없음, GitHub Actions 최소 권한 및 액션 SHA 고정. CSP 메타 태그로 외부 연결을 금지하고 자체 스크립트·스타일만 허용한다. GitHub Pages는 사용자 지정 응답 헤더를 지원하지 않으므로 메타 태그로 설정할 수 없는 frame-ancestors 등의 헤더는 제공하지 않는다. 금융·로그인·결제 등 민감 기능을 제공하지 않는 범위다.

KESE-KIT JavaScript 시큐어코딩 체크리스트의 입력 검증·XSS·비밀 관리·API 오용 항목을 참고했다. 전체 인프라 인증 또는 모든 취약점이 없다는 보장을 의미하지 않는다.

공개 후 실제 HTTPS·OG HTML·공개 PNG·비밀 경로 404·답글 생성·복사를 별도로 확인한다. 공개 기능에는 서버 요청 제한이 필요하지 않으며 호스팅 트래픽 제한은 GitHub Pages 정책을 따른다.

## 확인한 구현과 근거

| 경계 | 적용 및 확인 |
|---|---|
| 인증·권한 | 서버 코드 확인, 앱 ID·reader 역할 검증, 다른 앱 세션 거부 |
| 비밀값 | setup에서 난수 생성, 비공개 환경 파일, 파일 모드 0600, 빌드·공개 파일에서 제외 |
| 코드 비교 | salt와 scrypt, timingSafeEqual 사용 |
| 세션 | HMAC 서명 검증, 30일 만료, 앱 코드 버전 변경 시 해당 세션 무효화 |
| 쿠키 | HttpOnly, SameSite=Strict, 앱별 Path. HTTPS origin에서 Secure |
| 위조 요청 | 변경 요청은 정확한 Origin 일치 요구. 채널 파라미터로 권한 부여 불가 |
| 입력 제한 | 요청 8KiB, 리뷰 500자, 메뉴 20자, 허용된 필드·열거값 검증 |
| XSS | textContent로 사용자 입력 표시, HTML로 삽입하지 않음. 실제 브라우저 검증 |
| 파일 노출 | 허용된 공개 파일만 반환. .env와 서버 소스 접근 시 404 |
| 요청 남용 | 앱·작업·접속 주소별 제한, 시간창 만료, 저장키 상한, 응답 429 |
| 정보 유출 | 내부 예외 메시지 미반환, 리뷰·코드·결과 로그 미기록, Cache-Control no-store |
| 보안 헤더 | CSP, frame 제한, nosniff, referrer 제한, 센서 권한 제한 |
| 공급망 | 외부 npm 런타임 의존성 없음. Node 런타임 자체 업데이트는 운영 시 관리 필요 |

데이터베이스, 파일 업로드, 명령 실행, 외부 URL 가져오기, XML 해석 기능은 없으므로 관련 공격 경로는 현재 코드에서 해당 없음으로 분류했다. 해당 기능을 추가하면 재검토해야 한다.

## 공개 배포 전에 남은 작업

- 단일 프로세스 메모리 제한기는 서버 재시작 시 초기화된다. 다중 서버·서버리스 환경에서는 공유 제한기로 교체해야 한다.
- 현재 접속 주소는 직접 연결된 소켓 주소만 사용한다. 임의의 X-Forwarded-For를 신뢰하지 않는다. 프록시 뒤 배포 시 신뢰할 프록시 범위를 별도 설정·검증해야 한다.
- Node 서버는 loopback에만 바인딩한다. 인터넷 공개 시 HTTPS 역방향 프록시 또는 검증된 서버리스 어댑터 필요.
- 코드와 세션 비밀을 운영 설정으로 새로 발급하고, 호스팅 로그가 리뷰 본문을 남기지 않는지 확인해야 한다.
- 잠그기는 현재 브라우저의 쿠키를 삭제한다. 별도 세션 저장소가 없는 구조라 이미 탈취된 토큰의 개별 즉시 폐기는 제공하지 않는다. 해당 앱 코드 교체로 일괄 무효화할 수 있다.
- 서버 검증이 있어도 공통으로 배포된 앱 이용코드가 공유되는 것은 막을 수 없다. 실제 결제 확인 서비스가 아니다.
- 심화편 소식 신청, 개인정보 저장, 실제 AI 연결은 미구현. 추가 시 동의·보관·외부 전송 범위를 다시 설계한다.

결론: 로컬 사용 경계의 기능·보안 검사 통과. 공개 배포 환경 점검은 미완료이며 이 보고서로 대체할 수 없다.

## 내장 브라우저 모드 전환 수정 (2026-09-26)

기존 공개 앱에서 내장 브라우저의 라이트 클릭 후 data-theme와 실제 배경색이 바뀌지 않는 현상을 재현했다. 문서 클릭 위임과 readyState 확인으로 초기화 시점 의존성을 줄였다. 수정본에서 light/#f3f3f3, dark/#181818 전환을 직접 확인했다. 저장값 및 클릭값을 light/dark로 제한하고 외부 전송은 추가하지 않았다. 기존 KESE-KIT 입력 검증·XSS 검토 범위를 유지한다.
